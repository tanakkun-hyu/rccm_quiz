 RCCM 問題データ 手編集ルール 早見メモ
 対象ファイル: data/q2.json （問題2の全問。1ファイル133問）
========================================================

■ どこを開く
・GitHub上: リポジトリ直下の data フォルダ → q2.json（鉛筆✎で編集）
・手元: 解凍した deploy_問題2/data/q2.json
・エディタ: VS Code などのテキストエディタ。Word/Excelでは開かない（壊れる）
・保存の文字コードは必ず UTF-8

■ ファイルの形
・先頭9行はメタ情報 → 触らない
・"questions": [ から下、{ … } のかたまり1つ＝1問
・目的の問題は Ctrl+F で問題文の語句か id（例 rccm-q2-081）で検索

■ 1問の中身（各キーの意味）
  "id"                … 内部の一意名（触らない）
  "category"          … 出題グループ名（下の13カテゴリーの正式名そのまま）
  "question"          … 問題文
  "question_image"    … 問題図のファイル名。無ければ ""
  "choice_1"〜"choice_4"        … 選択肢 a〜d（1=a,2=b,3=c,4=d）
  "choice_1_image"〜"choice_4_image" … 各選択肢の図。無ければ ""
  "answer"            … 正解番号。数字で 1〜4（a=1,b=2,c=3,d=4）※クォート無し
  "explanation"       … 解説文
  "explanation_image" … 解説図のファイル名。無ければ ""

※ 画面の「何問目」は id ではなく、そのカテゴリー内の"並び順"で決まる。

■ よくある編集
・文言/誤字の修正 : ダブルクォート " " の中の文字だけ書き換える
・正解を変える     : "answer": 2,   ← 数字を変えるだけ
・解説に改行を入れる : 文中に \n （半角バックスラッシュ+n）を入れる
                     例 "explanation": "1行目。\n2行目。",
                     （アプリは \n を改行として表示する）
・図を付ける       : 画像を images/ に置き、ファイル名だけ書く
                     例 "explanation_image": "rccm-q2-005_e.png"
                     命名の目安 問題図=id_q.png / 解説図=id_e.png / 選択肢図=id_c1.png
・カテゴリー変更/移動 : "category" を別の正式名に変える。
                       並び順を変えるなら { … } のかたまりごと切り取り→貼り付け。

■ 13カテゴリー（この文字列を category に入れる）
  資格制度 / CPD / 倫理 / プロポーザル・総合評価 / 標準委託契約約款 /
  積算基準 / 共通仕様書 / 成績評定 / 品確法 / 知的財産権 /
  国土交通白書 / 第6次社会資本整備重点計画 / 時事問題等

■ 壊さないための鉄則（JSONは厳格）
  1) { } のかたまり同士はカンマ , で区切る。
     ★最後の要素・最後のかたまりにはカンマを付けない（閉じ括弧の直前はカンマ無し）
  2) キーも文字列も必ず半角ダブルクォート " で囲む（全角 “ ” は不可）。
     answer の数字だけクォート無し。
  3) 文中で " を使うときは \" 、\ を使うときは \\ と書く（日本語では稀）。
  4) 保存は UTF-8。

■ 反映の手順
  q2.json を保存 → GitHubで Commit changes → 1〜2分 → スマホで強制リロード
  （図を足したら images/ への画像アップロードも必要。index.html は触らなくてよい）

■ 事故防止（強く推奨）
  Commit する前に、q2.json の全文を https://jsonlint.com/ に貼って
  「Valid JSON」と出ることを確認する。カンマ1個の抜けで全問が表示されなくなるため。
